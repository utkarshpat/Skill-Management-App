# Current checkout audit — 10 October 2026

Reviewed the current uncommitted implementation with the approved Access Management baseline. Traced Business Operations administration, scoped reads/export, amendment and demand SQL, effective-access discovery, AI tools/conversations, frontend async transitions, identity-directory binding, certification/review/upload contracts, and shared request deduplication. Existing pending work was preserved. This is source review plus regression tests and synthetic browser/rollback SQL acceptance; it is not production, SSO or load-test acceptance and cannot establish that the entire repository is bug-free.

## Confirmed issues corrected

| Issue | Failure and correction | Evidence |
| --- | --- | --- |
| Scope lifecycle parity | Another live grant could keep Business Operations available while an inactive project or department beneath an inactive DU remained in selectors or authorized demand metadata. Shared SQL validity/usable-responsibility checks now drive discovery, selected reads, demand authorization and comparisons. Fully covered DENY bindings are excluded; overlapping partial DENY still subtracts people. Project authority remains independent of home departments. | Restricted-runtime scope-lifecycle rollback scenario; existing overlapping-project and DENY scenarios. |
| Incorrect amendment flag | Dashboard context returned `canAmend=true` even when the independent proposal action was denied. It now returns `BusinessAmendCan`. | Individual proposal DENY with analytics still allowed. |
| Administration prerequisite race | Administration read/save SQL checked permissions/users/audit but omitted own profile access. A revocation after API preview could still permit the transaction. SQL now independently checks the same profile prerequisite. | Restricted-runtime profile-denied rollback scenario. |
| Administration lockout | Responsibility changes could leave people with permissions/users management but nobody satisfying the full prerequisites needed to administer Business Operations. The retained-admin check now also requires current profile and audit access. | Last usable administrator removal rolls back. |
| Expiry timezone mismatch | API preview accepted offset timestamps, while SQL datetime2 could discard their offset and enforce a different expiry instant. Input now requires an explicit timezone and normalizes to UTC before preview/storage. | +05:30 normalization and timezone-less rejection regressions. |
| AI history and delivery revocation | Model context reset after permission changes, but old saved transcript/title could still be returned or appended to a resumed conversation. Replies also lacked a final recheck after asynchronous history save. History now redacts mismatched-policy transcripts/titles, rechecks delivery, and resumed saves omit old messages. Final chat delivery rechecks after persistence. Stored history is retained rather than silently deleted. | Durable-context, storage-I/O revocation and mid-generation scope tests; synthetic provider only. |
| Export metadata formulas | CSV record values were protected, but a scope label such as `=HYPERLINK(...)` was written to metadata without protection. Every metadata cell now uses the same control-character removal/formula guard. | CSV and XLSX Context sheet regressions. |
| Repeated matching hang | Clicking Find matches twice for the same demand on page one cleared results without changing effect dependencies, leaving permanent loading. A dedicated request-attempt dependency now triggers the second read. | Synthetic browser: two consecutive clicks return the candidate table. |
| Stale dataset sort | Chart/scope navigation could carry an expiry sort into a dataset whose selector did not support it. Dataset transitions now clear inherited sort unless the transition explicitly supplies a supported sort. | Deep-link filter transition regression. |
| Empty workflow body crash | Preview/save accessed properties on an undefined body, producing 500 instead of a validation response. Both endpoints now validate the outer object and permitted argument names. | Authenticated HTTP empty-body regression returns 400. |

Additionally, shortlist execution now compares the number of established requirements with the entire requested requirement count. A missing referenced master must fail closed rather than disappear from a join and bypass an `EXISTS(matched=0)` check. No reachable master-deletion API exploit was demonstrated; this is defensive hardening.

## Verification and release boundaries

Full repository tests, focused regressions, type checks, architecture checks, generated-document consistency and production builds are run for this increment. SQL fixtures use synthetic people/grants and rollback pending DDL, data and audit within the development database. Scope lifecycle, full-admin retention and profile denial have separate regression scenarios; no permanent migration or live access change is applied. Browser acceptance uses a loopback fixture without real people, SQL mutations or a paid model call.

Pending release work remains unchanged: migrations 059–061, reviewed Personal baseline/responsibility activation, authenticated hosted/SSO acceptance, live model-provider acceptance, and hosted latency/load measurement. Coarse serializable workspace locks, synchronous bounded exports and account-wide administration snapshots still need workload measurements before scale claims. Historical capability/domain-specific grants, asynchronous export jobs and chart/PDF exports remain outside the implemented increment.
