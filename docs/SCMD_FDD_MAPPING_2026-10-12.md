# SCMD FDD mapping against the current application

Reviewed 12 October 2026 against repository commit `6d4a899121babcdcefe116fefca5a09180ebc0e1`.

Source: `C:/Users/utpatel/Downloads/SCMD FDD V0.1.docx`. Its cover identifies version 1.0 and status Draft, although the filename says V0.1. This is a requirements comparison, not approval of a new baseline or a fresh production acceptance test. The original document and application behavior were not changed. Current repository code is the implementation basis; deployment and organization configuration must be verified separately.

The application's employee, exact current-manager review, scoped Business Analytics and Admin workspaces provide a substantial foundation for SCMD. The main gaps are Oracle master data and iReflect levels, certification business uniqueness, corporate email eligibility, Oracle-specific dimensions/reports, and durable lead/threshold/monthly notifications. Several differences are deliberate user-approved design choices rather than defects.

Status meanings: **Implemented** means a concrete code path exists; **Partial** means a narrower or incomplete implementation exists; **Difference** means current behavior conflicts with the FDD or uses a different approved model; **Missing** means no corresponding implementation was found in the reviewed code; **Future** means the FDD itself defers it; **Unverified** means environment evidence is still needed. These labels are not a claim of production sign-off.

## Extra implemented features

These exceed the supplied FDD. Extra does not mean they should be removed: many were explicitly requested by the user.

- Unified personal Skills portfolio, common three-stage intake, certificate preview/download, AI factual autofill, related-skill suggestions, single-expanded certificate accordion, expiry presets, recoverable group-draft removal, and renewal continuity/history.
- Independent skill/certificate decisions within one atomic request, immutable review snapshots, explicit current-manager rerouting, authorization explanations, scoped DENY and access-change preview/recheck/audit.
- Business demands, explainable matching and shortlists; multiple project memberships; scoped submitted-evidence viewing; whole-result XLSX as well as CSV exports.
- Provider/credential/skill amendment lifecycle with governed approve/update/retire behavior, current target revision checks and retry protection.
- Internal learning plans, tasks, goals, calendar/backlog, AI roadmaps/quizzes/chat; requests/incidents and other support workflows; knowledge-transfer guide.
- General enterprise catalogue, five-level framework and broader file formats. These are configuration/compatibility differences requiring decisions if Oracle-only Phase 1 becomes the approved target.

## Decisions needed before implementation

1. Confirm the approved document version and Oracle-only vs enterprise-wide scope. An Oracle community should not automatically become the application's security Account.
2. Obtain the official iReflect framework/criteria, approved Oracle skill/provider/credential list, certification levels and credential-to-skill mappings. Decide migration treatment for five-level historical claims.
3. Define printed Credential ID and business duplicate identity, renewal/version attempts, ownership validation and previous-organization exception rules.
4. Agree attachment types/limits: FDD 10 MB PDF/images versus current 5 MB certificates plus 10 MB ordinary image evidence. Preserve compression without changing the announced original-file limit.
5. Resolve lifetime expiry: recommend null internally, optional 2050 presentation only for a mandated external format.
6. Define Community, Practice, Pillar, Location and Account/Project relationships using canonical source IDs; decide permitted scopes separately from reporting dimensions.
7. Define lead/admin recipients, monthly summaries and below-70 semantics. Do not notify people merely because their role label says Lead/Admin.
8. Resolve the FDD's certificate creation timing, immediate-dashboard visibility and Rejected/Resubmitted wording. Keep private drafts private and approval distinct from expiry/issuer authenticity.

## Suggested delivery order

1. Lock the source requirements and decisions above; keep the already-approved access constraints.
2. Implement semantic certificate deduplication and any agreed mandatory printed ID, with transaction/race/retry tests. Fix corporate email eligibility against authoritative provisioned employee facts.
3. Configure approved Oracle masters and versioned iReflect support, then canonical master mapping. Retain human confirmation of AI output.
4. Finish unified manager navigation and end-to-end grouped intake/approval/report projections; avoid duplicate review rows and partial group decisions.
5. Add missing reporting fields/dimensions and certification-specific reports, ranks/leaderboards and scope-safe filters.
6. Add durable exception/lead/monthly/threshold notifications and the organization-hosted scheduler. In-app read-time reminders must not be presented as offline delivery.
7. Add governed legacy Excel/CSV import if required, then Oracle CertView/My Learn integrations as later phases.
8. Conduct company-hosting acceptance: SSO/employee synchronization, duplicate races, changed manager/access, one-to-many counts, approved-but-expired records, no-expiry, previous-company exceptions, export/file scope, encryption/backup/retention and scheduled delivery.
