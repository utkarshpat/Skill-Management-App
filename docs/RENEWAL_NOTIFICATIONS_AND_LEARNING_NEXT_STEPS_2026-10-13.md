# Renewal, notifications and completed-learning next steps

The renewal form retains credential family and issuer, resets the printed ID, verification link, validity and notes, and requires a newly uploaded certificate before Continue. Existing approved related skills are reused by default with employee confirmation; no new proficiency is assigned. Existing draft/submitted renewals open through Continue renewal rather than creating duplicates. The review summary shows the new ID, dates, filename and approval consequence.

Approval makes the renewed certificate the current portfolio version. The previous row/file stays in renewal history and old submission snapshots remain immutable. Pending/returned/rejected renewal keeps the old current version in place. An expired unrenewed certificate remains visible. The SQL current projection also feeds Business Analytics snapshots, demand matching and milestone reminders; immutable historical activity remains an event history. Old versions are not counted again as current holdings. Manager certificate aggregates cover pending and approved certificates assigned to the exact current direct manager, excluding superseded versions; no new private-file read scope is granted.

Notifications group by category and date, show the reviewing actor, subject, recorded outcomes and specific destinations. New combined decision audits capture immutable per-item outcomes. Reused records do not count as newly approved items. Earlier audits without outcome snapshots retain a general completion message and link; they do not invent historical counts. Read state remains per device and changing access still invalidates unavailable data.

Every nonempty completed learning plan offers Suggest next steps. Live acceptance caught the compact learning summary lacking exact plan identifiers, which caused the provider to guess a task lookup. The new my_learning_plan tool reads the exact own saved plan and authoritative completion totals, rejects foreign selectors, and includes plans beyond the summary preview limit. The explicit AI call verifies completion from `my_learning_plan`, then searches published skill and active credential catalogues. `credential_catalogue_search` uses a paginated SQL read returning ten canonical credential choices and up to ten published related skills per credential, with compact descriptions. It does not fetch personal claim narratives, files, or arbitrary actors. The UI offers Add skill and Upload earned certificate; suggestions never award a credential or establish proficiency.

Validation before rollout: API policy tests cover actor binding, private-data exclusion, result bounds and DENY for the new tool. Web tests cover completion eligibility, catalogue grounding prompts, notification destinations/dates, and retained expired versus superseded certificate display. Rollback SQL scenarios exercise renewal approval, returned renewal, old expiry-reminder suppression, corrected/resubmitted snapshot integrity, changed manager, incomplete decisions and rerouting.
