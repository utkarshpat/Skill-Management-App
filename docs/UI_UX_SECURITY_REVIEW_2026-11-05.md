## Reported functional gaps (requires SQL migration if changed)

- **Asymmetric archived-mapping validation between Skills and Certifications (`086` vs `078`/`087`):**
  - In `database/migrations/086_catalogue_forms_shared_criteria.sql` (line 48), `dbo.SaveSkillCatalogue` permits retaining an already-mapped retired certification (`AND NOT EXISTS(SELECT 1 FROM dbo.CredentialSkillMapping ...)`).
  - In `database/migrations/087_direct_catalogue_management.sql` (line 89) and `078_credential_skill_master_mappings.sql` (line 82), saving or approving a `CERTIFICATION` checks `LEFT JOIN dbo.SkillCatalogue c ON ... AND c.status='PUBLISHED' WHERE ... c.skill_id IS NULL` **without** exempting existing `CredentialSkillMapping` rows, even though `MASTERS` (`078` line 24) loads all mapped `skill_id`s (including archived skills) into `relatedSkillIds`. If a mapped skill is later archived, editing or retiring that certification fails with `Choose unique published skills from this account.` unless the archived skill ID is manually removed first.

## Security observations

No `dangerouslySetInnerHTML`/`eval`; every `target="_blank"` link inspected uses `rel` noopener; API uses `helmet` and disables `x-powered-by`; direct login is refused outside `NODE_ENV=development`. `localStorage` holds only theme, sidebar order and notification read state (no tokens). No new vulnerabilities found in the reviewed surface; this is not a full penetration review.

## Follow-up: executable flow and edge-case coverage

The user explicitly cancelled the Catalogue tab merge. Skills, Certifications and Amendments, their links and permissions are unchanged by this follow-up. The earlier Legacy review presentation is also outside this testing increment.

Tests now import the production modules rather than evaluating source excerpts. A shared Happy DOM/React `act` harness mounts the actual certification picker and intake-file hook. The auth tests use the real session, configuration, request-sharing and notification code, mocking only network responses, browser navigation/tab signals and the Microsoft SDK boundary. Each auth fixture reloads its entry point at the same source URL, avoiding duplicate coverage records caused by query-string module isolation.

Two regressions exposed by these tests are corrected:

- The staged-file hook could return the previous draft's file during the first render after its root changed. Returned state is now bound to the current root; old object URLs are revoked and late reads remain ignored. File metadata is typed and validated before the binary request, and the file ID is encoded as one path segment.
- A successful but malformed certification-choice response could reach rendering and throw instead of exposing the existing error/retry state. Invalid choices now take that recovery path; non-Error failures in both surfaces also retain a useful visible message.

No grants, SQL procedures, review relationships, workflow mutation policies or stored files are changed. This is automated component/integration coverage with synthetic data, not live Entra/MFA, installed-SQL acceptance, layout/screen-reader certification or a guarantee that every application flow is bug-free. Happy DOM does not fully implement disabled-fieldset click suppression; the test verifies the native disabled-fieldset contract rather than claiming real-browser interaction acceptance.
