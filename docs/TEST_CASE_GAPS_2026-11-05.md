## Automated regression additions

`apps/api/test/auth-boundaries.test.ts` exercises the real signed-token verifier with synthetic RSA keys: omission of each required claim (`exp`, `iat`, `nbf`, `tid`, `oid`, `scp`, `azp`, `ver`), application roles without delegated scope, scope prefix/suffix/case/empty mismatches, multiple valid scopes and malformed/oversized authorization headers. Existing auth tests separately exercise wrong signatures, tenant, audience, caller, expiry and future-not-before.

Three additional `microsoft-session.test.tsx` cases exercise redirect-result account selection, preservation of an already selected active account, and retry after redirect-processing failure without premature cached-user selection. Existing tests cover concurrent initialization, SDK load/init retries and ambiguous multiple accounts. These are real module tests, not an authenticated browser/SQL walkthrough.

## Release gate

The coverage run uses Windows/Node 26.8.2. The repository CI targets Ubuntu/Node 24; that exact target/version combination was not executed by this local report. Verify CI and Linux deployment separately, including native file/image dependencies and casing/path behavior.

Automated checks passing is necessary, not sufficient. Prioritize UI-02/04/05/08, DB-01–09 and AUTH-01–04 before claiming complete real-user acceptance. Then mobile/keyboard/theme and manager navigation. No full penetration test, live database coverage percentage or complete requirements-coverage percentage is claimed.
