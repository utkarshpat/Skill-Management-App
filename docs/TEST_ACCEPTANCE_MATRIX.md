# Workflow and edge-case acceptance matrix

Target requested by the user: **90%+ coverage**, with realistic human-readable fixtures and reasoned workflow cases. This is an active target, not a completed acceptance statement. `npm run coverage:check` requires 90% for lines/statements/branches/functions in each app and complete TypeScript source representation. No production files are omitted except `.d.ts`. SQL and CSS are outside TypeScript coverage; a passing percentage cannot establish their acceptance.

Fixtures use fictional Aditi Menon, Rohan Mehta and Neha Kapoor with delivery projects, skills, certificates and reporting relationships. Test adapters never seed or mutate the real company workspace. Browser HTTP fixtures, driver contract tests and installed-SQL acceptance are different evidence levels.

## Cross-cutting cases required for every mutable flow

| Boundary                                              | Expected result                                                                   | Evidence requirement                  |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------- |
| Empty/invalid/overlong/unknown fields                 | Explain validation; preserve valid entries; no write                              | Unit plus browser form case           |
| Foreign actor/account/resource/scope                  | Server resolves authenticated actor and resource; reject expansion                | API plus installed SQL                |
| Inactive user, expired grant, scoped DENY             | Current decision overrides cached discovery; no delivery/write                    | Policy/API plus installed SQL         |
| Missing, changed or cyclic manager assignment         | Fail closed; no role-name or hierarchy shortcut                                   | Relationship tests plus installed SQL |
| Stale revision, duplicate click, lost acknowledgement | Conflict or idempotent recovery; no duplicate audit/write                         | Browser, adapter and installed SQL    |
| Offline/timeout/429/partial response                  | Safe error, useful retry, bounded work; no false success                          | API/provider/browser                  |
| Abort, route change, logout, newer response           | Old response cannot restore or overwrite current state                            | Browser race and session tests        |
| Private file retrieval or upload                      | Authorize before IO and recheck before delivery; reject changed/truncated content | Adapter plus installed storage tests  |
| Keyboard/mobile/theme                                 | Reachable actions, focus recovery, readable status and no page overflow           | Browser plus visual check             |
| Discovery vs execution                                | Only implemented actions; execution rechecks the same scope and relationship      | Projection/API/SQL comparison         |

## Release boundary

Do not label the build release-ready while the 90% gate or critical behavioral acceptance is incomplete. Thirty-nine installed-SQL suites were previously blocked by the lack of an approved isolated target. A new local-only `SkillMgmt_PortfolioAudit_*` SQL Express database was subsequently created for the separate [e37df62 hierarchy audit](PORTFOLIO_COMMIT_AUDIT_2026-11-05.md). Migrations through 088 and bounded scope/mapping SQL checks passed there. No existing/company database or application connection configuration was changed. The application adapter still accepts Azure SQL hosts/Entra auth only; these raw SQL checks do not constitute the 39 application integration suites or prove Azure identity/RBAC behavior.

Record actual passes, failures, skipped cases, exact environment and known defects. Do not replace a failing assertion with a weaker one to reach a percentage. Do not claim all conceivable edge cases are exhausted.
